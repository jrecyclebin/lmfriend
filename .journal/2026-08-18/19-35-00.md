# lmfriend first implementation session

Built the full tool from design.md after the viability probe. Key learnings:

- **SDK facts (ModelContextProtocol.Core 2.2.0)**: `HttpClientTransport.ConnectAsync()` returns
  `ITransport`; `AuthorizationCallbackHandler` is `Func<AuthorizationCallbackContext, CancellationToken, Task<AuthorizationResult?>>`
  (returns an `AuthorizationResult` with Code/State/Iss, not a string). `ClientOAuthProvider`
  is constructed with the same HttpClient handed to HttpClientTransport — the cert bypass
  reaches OAuth calls too. `TokenContainer` round-trips the DCR client creds; persist it whole.
- **HttpListener is a trap for loopback OAuth on Windows** (needs admin/URL ACL). Used a raw
  TcpListener + minimal HTTP instead. Redirect port prefers 48231-48239 for DCR redirect_uri stability.
- **Mid-session re-auth**: the SDK only exchanges the code when the callback task completes,
  so the pending request parks during the browser flow (2min timeout). Couldn't error it
  instantly without reimplementing the token exchange — flagged as design deviation; J should
  confirm or push back.
- MCP SDK POSTs with chunked transfer-encoding — the python mock mock initially read
  Content-Length only and silently swallowed every request. Always handle chunked in mocks.
- Proxy pump architecture that worked: single stdio writer channel; per-connection Session
  with SendLock + Outstanding id set + Dead TCS; cached init replayed with `lmfriend-init-N`
  ids, response swallowed except first connect (id swap answer to the client's waiting init).
